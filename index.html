Service-record screening

Only synthetic data loaded: ratio analysis disabled for operational conclusions.

A high number of residents per residential meter can arise from shared meters, multiple households in one building, mismatched meter classes, inaccurate service boundaries, population-model uncertainty or outdated GIS surveys.

Suggested verified workflow

1. Confirm meter status and residential category.

2. Import modelled population for the same geographic units.

3. Validate households and network supply zones.

4. Compare coverage and inspect exceptions.

Do not classify a consumer or locality as electricity theft using population alone.

Import aggregate population and meters

Upload a CSV with cell_id,population,active_meter_count. You can provide either or both numerical columns. Blank values remain missing—not zero. Every imported field is labelled by source.

Privacy: use aggregated counts only. Do not upload customer names, addresses, meter serial numbers or proprietary utility files to this public demonstration.

Import rules

Cell IDs range from D-01-01 to D-12-12 in a fictional grid. Values must be non-negative; meter counts must be whole numbers. Real population from geographic data cannot meaningfully be assigned to a fictional cell without a valid spatial crosswalk.

Use the separately maintained private GIS application to aggregate real WorldPop rasters to actual GIS feeder, transformer and planning-cell polygons.
